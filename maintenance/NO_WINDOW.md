# NO_WINDOW：生产维护，不做效果窗口实验

`NO_WINDOW` 在此表示本流程豁免于效果实验窗口，不表示豁免生产校验。目录更新是受门控的维护任务：每轮均检查来源、许可证、数据模式、引用和网站行为，再决定是否提交目录。

这项维护机制的北极星是每次发布零许可证、来源和模式错误，并保持 GitHub canonical catalog 与公开页面一致。自动生成的双语描述须经独立第二轮审核；来源失败或质量门未通过时整轮停止，线上维持上一版。

无变化也要保留每日健康收据。成功的 no-change 收据表示当天的来源抓取、目录核验和浏览器检查链完成；它不表示新增技能，也不提供技能执行效果的统计结论。失败由 GitHub Actions 原生通知触发，不另发邮件。

这里不以点击率、交易收益或执行成功率评估自动更新，因为该流程不执行被收录的技能，也不代表技能经过实盘、宿主兼容性或收益实验。实际效果若要研究，应另立明确的、经授权的实验设计，不得把维护收据改称效果证据。

自动维护可在既定金融投研范围内发现公开 GitHub 来源，须通过原文件、许可、两轮内容审核和网页校验。自动维护不得扩大金融投研任务边界或改动 schedule、secrets 和 workflow 权限。边界变更通过 Pull Request 由维护者审阅。已收录来源根许可证变化或全轮累计超过 6 条现有技能来源变更时，停止该轮并转人工处理。
